# Report Reference

The Markdown report (`report.md`) is a CEO-grade executive intelligence document generated by the Markdown Exporter. It is deterministic: identical input produces identical output.

## Report Structure

The report contains the following sections in fixed order:

1. **Executive Scorecard** — Scan signal summary
2. **Executive Summary** — Business overview and scan outcome
3. **Business Snapshot** — Business category, audience, content strategy, and maturity
4. **Signal Coverage** — Per-area coverage scores
5. **Website Overview** — Classification, metadata, and technical signals
6. **Scan Limitations** — Present only when the scan was restricted by anti-bot measures, timeouts, or robots.txt
7. **SEO Analysis** — On-page SEO evidence
8. **Metadata Analysis** — Brand and device metadata
9. **Technology Stack** — Detected technologies with purpose and confidence
10. **Technology Maturity** — Infrastructure, security, and client-side maturity
11. **Content Analysis** — Topics, keywords, and content inventory
12. **Social Presence** — Detected social platforms
13. **Competitive Signals** — Competitor references
14. **Top Strengths** — Up to 5 evidence-backed strengths
15. **Improvement Opportunities** — Priority-ranked gaps with potential benefit
16. **Executive Recommendations** — Priority/impact table
17. **Technical Diagnostics** — Scan metrics and evidence count
18. **Evidence Appendix** — First 20 evidence items with full JSON export note

> **Note:** Some sections appear only when relevant. For example, `Scan Limitations` appears when the scan was restricted by anti-bot challenges, timeouts, or robots.txt rules. `Data Completeness` appears when the scan completes with partial coverage.

## Section Reference

### Executive Summary

One-paragraph business overview including:

- Target URL and scan timestamp
- Health score (0–100)
- Website classification with confidence level
- Key evidence counts
- Business-friendly takeaways

### Scan Limitations

Transparent disclosure of scan constraints:

- Sites blocked by `robots.txt`
- Anti-bot challenges detected
- JavaScript-dependent content not captured
- Timeout or network failures
- Partial scan explanations

### Website Classification

Deterministic business category assigned to the target:

| Classification | Description |
|----------------|-------------|
| SaaS Platform | Software-as-a-Service products |
| E-Commerce Platform | Online stores and marketplaces |
| Corporate Website | Enterprise and business sites |
| Documentation Portal | Technical documentation |
| Blog / Content Site | Content-first publications |
| Agency / Services | Professional services firms |
| Media / Publishing | News and media outlets |
| Education | Academic and learning platforms |
| Government | Public sector and government |
| Non-Profit | Charities and NGOs |
| Unknown | Insufficient evidence to classify |

Confidence level: `high`, `medium`, or `low`.

### SEO Summary

On-page SEO signals extracted from the target:

- Page title and meta description
- Canonical URL
- Heading hierarchy (H1–H6 distribution)
- Open Graph tags
- Twitter Card tags
- Structured data presence
- Indexability flags
- Hreflang annotations
- AMP detection

### Metadata Summary

Structured head metadata:

- Favicon and app icons
- Language and charset
- Manifest links
- RSS/Atom feeds
- Verification tags (Google, Bing, Yandex, Facebook)
- Resource hints (dns-prefetch, preconnect, prefetch, preload)
- CSP meta tags
- msapplication tags
- Geo metadata

### Technology Summary

Detected technology stack:

- Frontend frameworks (React, Next.js, Vue, Nuxt, Angular, Svelte)
- CMS platforms (WordPress, Drupal, Joomla, Ghost, Shopify, Wix, Squarespace)
- Web servers (nginx, Apache, IIS)
- Analytics tools (Google Analytics, GTM, Plausible, Matomo)
- CSS frameworks (Bootstrap, Tailwind CSS)
- CDN providers (Cloudflare, Fastly, Akamai)
- Security headers (HSTS, CSP, X-Frame-Options, X-Content-Type-Options)
- Server signals (X-Powered-By, Via, X-Cache)

### Content Summary

Structured body content analysis:

- Heading distribution (H1 count, H2 count, etc.)
- Paragraph count and average length
- List count (ordered and unordered)
- Table count
- Image count with alt text coverage
- Link count and internal/external ratio
- Form count
- Contact information (emails, phones)
- Media elements (videos, audio)
- Breadcrumb presence
- Footer content summary

### Social Presence Summary

Discovered social profiles:

- Platform name (e.g., Twitter, LinkedIn, GitHub, YouTube)
- Profile URL
- Discovery method (page link, JSON-LD, Open Graph, icon class)
- Confidence level
- Provenance (page URL and DOM path)

### Competitor Summary

Resolved competitor comparison set:

- Competitor name
- Competitor URL
- Discovery method (explicit mention, "vs" heading, schema.org markup, user-supplied)
- Confidence level

### Diagnostics

Scan metadata and evidence counts:

| Metric | Value |
|--------|-------|
| Total Evidence Items | Count |
| SEO Items | Count |
| Technology Items | Count |
| Content Items | Count |
| Metadata Items | Count |
| Social Items | Count |
| Competitor Items | Count |
| Scan Duration | Seconds |
| Pages Scanned | Count |

### Data Completeness

Missing data explained with remediation guidance:

- SEO signals missing and why
- Technology signals not detected
- Social profiles not found
- Competitor signals absent
- Content extraction gaps

Each gap includes a plain-English explanation of why the data is missing (anti-bot, JS rendering, robots.txt, etc.) and what the user can do about it.

## Evidence References

Every factual claim in the report traces to one or more evidence IDs in the JSON output. Evidence references are preserved as Markdown links where applicable.

## Report Date

The report date uses calendar date only (deterministic within a single day). Timestamps in the JSON output are ISO-8601 UTC.
